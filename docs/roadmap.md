# Roadmap

[English](roadmap.md) | [繁體中文](roadmap.zh-TW.md)

## Current direction

The project keeps the public `gitlab-self-hosted` plugin **endpoint-neutral** while shipping the MCP server implementation in the same repository.

Normal remote usage should be:

```text
public plugin
  + user/workspace-selected HTTPS /mcp endpoint
  + OAuth
  -> GitLab
```

The public package must not embed a maintainer-specific deployment URL or silently select localhost.

## Near term

- Keep GitLab read/write tool coverage stable across GitLab.com, Self-Managed, and Dedicated.
- Expand compatibility fixtures across more GitLab Self-Managed versions.
- Improve capability probing and error messages for unsupported GitLab APIs.
- Add more granular per-tool and per-project authorization policy.
- Improve observability, audit events, and operational metrics for hosted deployments.
- Keep OAuth/CIMD/DCR interoperability tested against current MCP clients.

## Packaging and installation

- Maintain one public marketplace root for the workflow plugin.
- Keep real remote MCP URLs in user/workspace configuration.
- Keep `workspace-binding/.mcp.remote.json.example` as a neutral reference only.
- Keep localhost as an explicit development fallback generated by `build_local_variant.py`.
- Retain personal/App-bound builders only as backwards-compatible helpers, not as the normal installation path.
- Add or adopt a managed App Template only if the target platform provides a stable, documented template mechanism appropriate for self-hosted GitLab configuration.

## Security

- Preserve read-only defaults.
- Preserve separate merge enablement.
- Keep project allowlists authoritative.
- Prevent public source files from containing real organization MCP endpoints or OAuth secrets.
- Continue SSRF protections for remote metadata/endpoint validation.
- Preserve encrypted OAuth persistence and atomic multi-replica token/state handling.

## Future workflows

Potential additions include release workflows, members, milestones, richer CI diagnostics, and more GitLab administrative operations where they can be exposed with clear least-privilege controls.
